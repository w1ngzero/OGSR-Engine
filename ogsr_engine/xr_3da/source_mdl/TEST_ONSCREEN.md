# Проверка на экране: импорт Source-.MDL в движок (скелет + анимации)

Офлайн-связка проверена (об этом — VERIFICATION.md, Раунды 15–16). Ниже — минимальный
сценарий проверки в самой игре. Он же показывает, как разделить «не запустилось из-за
консоли» и «реально не работает импорт».

---

## 1. Консольные команды — ОБЯЗАТЕЛЬНО включить

Оба ключа по умолчанию `0` (импорт **выключен**!). Без них Source-импорт не запускается,
и модель уйдёт в запасную ветку (см. §3). Включить в консоли или в `user.ltx` / `autoexec.cfg`:

```
rs_source_skeleton 1
rs_source_mesh 1
```

> Запомнить: если после включения `rs_source_skeleton` в логе НЕТ строки `[importer-v2]` —
> значит, запущен `xrEngine` из старых исходников, а не новой сборки.

## 2. Что положить в gamedata

Движок ищет `.mdl` **рядом** с `.ogf`: убирает расширение у имени визуала и берёт `<имя>.mdl`.

В `gamedata/meshes/` (папка `game_meshes`) для модели `<name>` положить:

- `<name>.ogf` — скелетный визуал **без** чанка `OGF_S_BONE_NAMES`, но с геометрией
  (это и есть «геометрия без скелета», из которой импортёр берёт кости/анимации);
- `<name>.mdl` — Source-файл модели (тот самый, который ты гоняешь в офлайне, напр. `v_knife.mdl`).

Имя модели, по которой гоняешь тест, должно совпадать с именем визуала в игре.

## 3. Ожидаемые строки в логе

При успехе (обе консольные команды включены, `.mdl` найден):

```
[SourceSkeleton] imported skeleton for '<name>' (<N> bone(s)) [importer-v2]
```

Если скелет импортировался, но геометрии нет / не нужна — будет:

```
!! [SourceMesh] could not attach geometry for '<name>' (mesh import failed)
```

ЕСЛИ анимации построились: в `SkeletonAnimated.cpp` ветка `m_source_imported` создаёт слот,
который потом проигрывается по имени (`idle`,`draw`,`holster`,`inspect`,…). Ошибки вида

```
!! [SourceAnimations] could not create motion slot for '<name>'
```

говорят о проблеме с чтением OMF (по ним можно смотреть `source_mdl_anim_to_xray.cpp`).

## 4. Что проверить на экране

1. **Тип визуала** — модель должна прийти как `MT_SKELETON_ANIM` и создать
   `CKinematicsAnimated` (не заглушку, не пустой `CKinematics`).
2. **Поза скелета** — bind-pose / первый кадр: кости стоят в правильном положении, «разброса»
   частей модели нет (иначе — проблема в `CalculateM2B` / порядке костей).
3. **Проигрывание анимаций** — смена `idle → draw → holster → inspect`: руки/модель двигаются,
   а не стоят на месте (если стоят — слот пустой или анимации не читаются).
4. Разумно проверить `walk_loop`/`jump` для скелета с движением.

## 5. Как проверить именно `wpn_hud` (оружие в руках), если нет `.ogf` и `.omf`

**Короткий ответ: `.ogf` и `.omf` не нужны вообще.** Движок при отсутствии `<name>.ogf`
автоматически соберёт весь визуал (скелет + геометрия + анимации) из сопутствующего
`<name>.mdl` (см. `TryAutoBuildSkeletonOGF`/`CModelPool::Instance_Load`, в логе метка
`[SourceModel] auto-built '...' from companion .mdl`). Нужны только Source-файлы:
`<name>.mdl` (+ `<name>.vvd`/`<name>.vtx` для геометрии).

(Раньше предлагалась ручная `.ogf`-заглушка — она больше не нужна и не рекомендуется:
у скелета он должен быть с чанком `OGF_CHILDREN`, иначе `FHierrarhyVisual::Load` → FATAL.)

### Откуда берётся имя визуала для HUD-оружия

`player_hud::load`/`attachable_hud_item::load` берут модель по ключам конфига (см. `HudItem.cpp`,
`player_hud.cpp`):

- `hud = <hud_sect>` — в секции оружия (`wp_knife` и т.п.);
- в `<hud_sect>` модель предмета (то, что висит на руках) задаётся ключом `item_visual`
  (или `visual`, если `item_visual` нет) → вызывается `::Render->model_Create(имя)`.

### Минимальная проверка HUD

1. В `gamedata/meshes/` положи Source-файлы ножа:
   - `v_knife.mdl` (+ `v_knife.vvd`, `v_knife.vtx` для геометрии).
   `.ogf` НЕ нужен (движок соберёт его сам из `.mdl`).
2. В `gamedata/configs/...` в секции `hud_sect` предмета замени модель на `v_knife`:
   ```
   item_visual = v_knife
   ```
   (или `visual = v_knife`, если `item_visual` не используется).
3. Включи консольные ключи (§1): `rs_source_skeleton 1`, `rs_source_mesh 1`.
4. Возьми оружие в руки → проверь: модель видна (поза костей) и проигрывается анимация
   (`idle`/`draw`/`holster`/`inspect`).

> Если руки в `player_hud` — старые вэнильные, а «новый» предмет подцепился — это нормально:
> для проверки импорта достаточно, что сам предмет виден и анимируется. Замена самих рук —
> отдельный шаг.

### Что смотреть в логе

- `[SourceSkeleton] imported skeleton for 'v_knife' ... [importer-v2]` — скелет из `.mdl` подхвачен.
- Отсутствие ошибок `!! [SourceAnimations] ...` — анимации прочитались.
- Если есть `!! [SourceMesh] ... mesh import failed` — геометрия не прикрепилась (проверь
  `rs_source_mesh 1` и наличие валидного меша в `.mdl`).

## 6. Если что-то не так

| Симптом | Причина / что делать |
|---|---|
| Нет `[importer-v2]` в логе | `rs_source_skeleton` не включён, или запущен не тот бинарник (не новой сборки) |
| `no companion .mdl` | `<имя>.mdl` лежит не там / имя не совпадает с визуалом |
| Модель грузится, но статична | `rs_source_mesh 0`, геометрия не подцепилась; и/или анимации не проигрываются — см. лог `[SourceAnimations]` |
| Вылет / чёрный экран | воспроизвести на `-debug`, снять отчёт; сравнить с Раундом мягкого фолбэка (см. §6) |

## 7. Про «вылет после спавна» (актуально)

Вылет, который ты видел ранее, — **не регрессия** импортёра: тогда не были прописаны
консольные команды, и модель уходила в ветку, которая раньше была **жёстким**
`R_ASSERT2` («нет OGF_S_BONE_NAMES и Source-импорт выключен») — отсюда креш.

Сейчас эта ветка переведена в **мягкий фолбэк**: строится одно-корневой identity-скелет,
визуал грузится статично, в лог пишется:

```
!! [SourceSkeleton] '<name>': no OGF_S_BONE_NAMES and Source skeleton import off/failed - using single-root fallback skeleton (static, non-animated).
```

То есть при включённых консольных командах и правильном `.mdl` — идёт полноценный импорт;
при выключенных/ошибочных — модель **грузится, но статичная**, а не вылетает.
